# Life OS — десктопное приложение для Linux

Нативная обёртка над панелью Life OS. Интерфейс и агенты живут на сервере
(`https://lifeos.dktunnel.xyz`), приложение даёт то, чего нет в браузере: трей, системные
уведомления, глобальные горячие клавиши и автозапуск.

Сделано на **Tauri v2 (Rust)**, интерфейс — тот же React, что и на сервере.

## Почему не Electron

Electron на этой машине стоил бы 200–400 МБ памяти на одно окно. Tauri — 40–80 МБ. Панель
открыта весь день, и разница в сотни мегабайт здесь принципиальна.

## Почему интерфейс не копируется в приложение

`tauri.conf.json` указывает `build.frontendDist` прямо на адрес сервера. Смысл: панель на сервере
достаёт и обновляет интерфейс, а приложение всегда показывает свежую версию без пересборки.
Обратная сторона честно названа: без сети приложение не откроет панель (сама оболочка запустится).

## Заметка о конфиге

В `tauri.conf.json` **нельзя** оставлять комментарии и ключи-подсказки вида `"//"`: Tauri
отвергает неизвестные поля, и сборка падает на этапе build-скрипта с невнятным сообщением
`unknown field`. Пояснения живут здесь, в README.

## Как скачать (без сборки у себя)

Сборка выполняется на сервере Life OS, готовые файлы лежат в `/root/lifeos-desktop-dist` и
раздаются панелью: **Настройки → Система → «Сборка для настольного компьютера»**. Раздача
закрыта тем же входом, что и панель, и доступна только администратору.

На Arch:

```bash
chmod +x lifeos-0.1.0-x86_64.AppImage
./lifeos-0.1.0-x86_64.AppImage
```

AppImage несёт все библиотеки внутри, поэтому системные зависимости для запуска не нужны.
Размер 83 МБ — из них само приложение 6,1 МБ, остальное webkit и GTK.

### Что нужно для сборки на сервере (Ubuntu)

```bash
apt-get install -y libwebkit2gtk-4.1-dev libgtk-3-dev libayatana-appindicator3-dev \
                   librsvg2-dev patchelf libssl-dev build-essential pkg-config file xvfb
```

`file` обязателен для `appimagetool` — без него AppImage не собирается, и ошибка выглядит
невнятно («failed to run plugin: appimage»).

## Установка (Arch) — если собираешь сам

```bash
cd desktop
bash install-arch.sh
```

Скрипт сам поставит зависимости через pacman, Rust, соберёт приложение и создаст ярлык в меню.
Сборка с нуля занимает 20–40 минут (компилируется около 400 пакетов), повторная — секунды.

## Что умеет

| Возможность | Как |
|---|---|
| Трей | иконка в трее, меню: открыть / свернуть / выйти |
| Свернуть вместо закрытия | крестик прячет окно в трей |
| Горячая клавиша | `Ctrl+Alt+Space` — показать/спрятать из любого приложения |
| Уведомления ОС | всплывают вместе с уведомлениями в панели |
| Автозапуск | тумблер в Настройках → Система |
| Один экземпляр | повторный запуск поднимает уже открытое окно |

Горячую клавишу можно сменить переменной окружения:

```bash
LIFEOS_HOTKEY="Ctrl+Shift+Space" lifeos
```

Поддерживаются `Ctrl`, `Alt`, `Shift`, `Super` и клавиши-буквы/цифры/пробел.

## Устройство

```
desktop/
├── install-arch.sh              установка на Arch
└── src-tauri/
    ├── Cargo.toml
    ├── tauri.conf.json          окно грузит сервер, трей, иконки
    ├── capabilities/
    │   └── remote-panel.json    права нативных вызовов ДЛЯ домена панели
    ├── icons/                   иконки приложения и трея
    └── src/
        ├── main.rs              точка входа
        ├── lib.rs               трей, хоткей, команды, автозапуск
        └── util.rs              чистая логика + тесты (проверяется без GTK)
```

Права в `capabilities/remote-panel.json` выданы **только** домену панели: если бы в окно
попал посторонний сайт, он не получил бы доступа к системе.

## Проверка

Логика в `src/util.rs` покрыта тестами и проверяется без графической стеки:

```bash
cd src-tauri && cargo test
```

(тесты лежат в самом `util.rs`; полная сборка приложения требует webkit2gtk и GTK.)

## Чего пока нет

- офлайн-режима;

- сборки под Windows и macOS.
